## Виклад

### 1. Чому словника вже не хватає (6 хв)

На дні 22 учні складали «картку об'єкта» словником:

```python
car = {"brand": "Toyota", "model": "Corolla"}
```

Питання класу: **а де тут «запустити двигун»?** Дані є, дій немає. Можна
написати окрему функцію:

```python
def start_engine(car):
    print(f"Двигун {car['brand']} {car['model']} запущений")
```

Ще питання: **що станеться, якщо в словнику зробити описку в ключі?** (Згадай
день 22, крок 4.6.) Нічого — програма тихо створить новий ключ і зламається
пізніше.

**Клас** розв'язує обидві проблеми: дані й дії, які з ними працюють, лежать
разом і мають чітко визначений набір.

Аналогія з лекції, з якої варто почати: **клас — це креслення будинку, об'єкт —
конкретний будинок**. Креслення одне, будинків за ним можна побудувати сто, і
всі вони різного кольору.

### 2. Клас, об'єкт, `__init__`, `self` (14 хв — головна частина)

```python
class Car:
    def __init__(self, brand, model):
        self.brand = brand      # атрибут об'єкта
        self.model = model

    def start_engine(self):
        print(f"Двигун {self.brand} {self.model} запущений.")
```

```python
car1 = Car("Toyota", "Corolla")
car2 = Car("Ford", "Focus")

car1.start_engine()      # Двигун Toyota Corolla запущений.
car2.start_engine()      # Двигун Ford Focus запущений.
```

Розбір по частинах:

- `class Car:` — оголошення класу. **Ім'я класу — з великої літери**, це
  домовленість (`CamelCase`, не `snake_case`).
- `__init__` — **конструктор**. Викликається сам, коли створюють об'єкт.
- `self.brand = brand` — зберігаємо значення в об'єкті.
- `start_engine` — **метод**, тобто функція, яка живе в класі.

**Тепер про `self` — окремо й повільно.**

`self` — це **сам об'єкт**, для якого викликали метод. Коли пишемо
`car1.start_engine()`, Python насправді передає `car1` першим аргументом.

🖥 Покажи це буквально:

```python
Car.start_engine(car1)      # те саме, що car1.start_engine()
```

Три правила, які варто продиктувати:

1. `self` — **перший аргумент кожного методу**. Завжди.
2. Щоб звернутись до атрибута об'єкта зсередини методу — **`self.атрибут`**, не
   просто `атрибут`.
3. При виклику `self` **не передають** — Python підставляє його сам.

⚠ Типові помилки, які покажи одразу:

```python
def start_engine():                    # ⚠ забули self
    print(self.brand)
# TypeError: start_engine() takes 0 positional arguments but 1 was given

def start_engine(self):
    print(brand)                       # ⚠ забули self.
# NameError: name 'brand' is not defined
```

Обидві помилки отримає весь клас. Краще, щоб уже бачили.

### 3. `__str__` (6 хв)

```python
car1 = Car("Toyota", "Corolla")
print(car1)      # <__main__.Car object at 0x000001F...>
```

Некрасиво. Виправляється методом `__str__`:

```python
class Car:
    def __init__(self, brand, model):
        self.brand = brand
        self.model = model

    def __str__(self):
        return f"{self.brand} {self.model}"

print(car1)      # Toyota Corolla
```

`__str__` мусить **повертати рядок** через `return`, а не друкувати. Це гарна
перевірка того, чи засвоєно день 23: тут `print` усередині `__str__` не працює.

### 4. Наслідування (8 хв)

```python
class Animal:
    def __init__(self, name):
        self.name = name

    def speak(self):
        print(f"{self.name} робить звук")


class Dog(Animal):              # Dog успадковує від Animal
    def speak(self):            # перевизначає метод
        print(f"{self.name} гавкає")


dog = Dog("Рекс")
dog.speak()      # Рекс гавкає
```

`Dog` не має свого `__init__`, але отримав його від `Animal`. Це і є
наслідування: **не дублювати те, що спільне**.

Якщо дочірньому класу потрібен свій `__init__`, але й батьківський теж:

```python
class Cat(Animal):
    def __init__(self, name, color):
        super().__init__(name)      # покликали конструктор батька
        self.color = color

    def speak(self):
        print(f"{self.name} нявкає")
```

`super()` — звернення до батьківського класу. Без нього довелось би
переписувати `self.name = name` вручну.

⚠ Питання класу на розуміння: **де в житті ти вже бачив наслідування?** Гарна
відповідь — будь-яка ієрархія: транспорт → автомобіль → легковик; фігура →
чотирикутник → квадрат.

### 5. Поліморфізм (5 хв)

Одне ім'я методу, різна поведінка залежно від класу:

```python
animals = [Dog("Рекс"), Cat("Мурчик", "сірий"), Animal("Хтось")]

for animal in animals:
    animal.speak()
```

```
Рекс гавкає
Мурчик нявкає
Хтось робить звук
```

⚠ **Головна думка, яку варто донести:** цикл **не знає й не питає**, який саме
клас перед ним. Він просто каже `speak()`. Кожен об'єкт відповідає по-своєму.

Практична вигода: додали клас `Cow` — цикл **не змінюється взагалі**. Порівняй
із варіантом на `if`:

```python
for animal in animals:
    if isinstance(animal, Dog):
        print("гавкає")
    elif isinstance(animal, Cat):
        print("нявкає")
    # ... і так на кожен новий клас
```

Другий варіант доведеться правити щоразу. Це і є аргумент за поліморфізм.

### 6. Інкапсуляція (4 хв)

```python
class BankAccount:
    def __init__(self, balance):
        self.__balance = balance         # два підкреслення — приватний

    def deposit(self, amount):
        if amount > 0:
            self.__balance += amount
        else:
            print("Сума мусить бути більше 0")

    def get_balance(self):
        return self.__balance


account = BankAccount(1000)
account.deposit(500)
print(account.get_balance())      # 1500
account.__balance = 1000000       # ⚠ це НЕ змінить баланс
print(account.get_balance())      # 1500
```

Дві підкреслені літери перед іменем роблять атрибут **приватним**: зовні до
нього не звернутись напряму.

Навіщо: **усі зміни проходять через метод, у якому є перевірка.** Не можна
покласти на рахунок −500, бо `deposit` це не дозволить.

⚠ Зв'яжи з блоком баз даних, це дуже точна аналогія: `CHECK` на дні 9 робив те
саме — не давав записати від'ємну суму. І процедури на дні 15 давали доступ до
даних лише через себе. **Інкапсуляція в коді — це те саме, що обмеження в базі.**

Скажи чесно: у Python приватність «за домовленістю», обійти її можна. Але код,
який ліз би в приватні атрибути, вважається зламаним.

## ⚠ Що піде не так

| Симптом | Причина | Що робити |
|---|---|---|
| `TypeError: method() takes 0 positional arguments but 1 was given` | забули `self` у методі | `def method(self):` |
| `NameError: name 'brand' is not defined` | забули `self.` перед атрибутом | `self.brand` |
| `print(obj)` дає `<object at 0x...>` | немає `__str__` | додати `__str__` із `return` |
| `__str__` нічого не змінив | усередині `print` замість `return` | `return` |
| Дочірній клас «забув» атрибути | свій `__init__` без `super()` | `super().__init__(...)` |
| `AttributeError: 'Car' object has no attribute 'brnd'` | описка | на відміну від словника, тут помилка **видна одразу** — це перевага класів |

### Відповіді

**Крок 1. Клас Student**

```python
class Student:
    def __init__(self, last_name, first_name, class_name):
        self.last_name = last_name
        self.first_name = first_name
        self.class_name = class_name
        self.grades = []

    def add_grade(self, grade):
        if 1 <= grade <= 12:
            self.grades.append(grade)
        else:
            print("Оцінка мусить бути від 1 до 12")

    def average(self):
        if len(self.grades) == 0:
            return 0
        return sum(self.grades) / len(self.grades)

    def __str__(self):
        return f"{self.last_name} {self.first_name} ({self.class_name}), середня {self.average():.2f}"
```

⚠ Три речі, які тут перевіряються одразу:

- `self.grades = []` створюється в `__init__` — **у кожного об'єкта свій
  список**. Якщо учень оголосить `grades = []` на рівні класу, список стане
  спільним для всіх, і це чудова помилка для розбору.
- перевірка діапазону в `add_grade` — це вже інкапсуляція, ще до розділу про неї
- `average()` для порожнього списку — та сама проблема, що на дні 23, крок 4.7

**Крок 2. Помилки з self** — навмисні, обидві з таблиці вище.

**Крок 3. Наслідування**

```python
class Person:
    def __init__(self, last_name, first_name):
        self.last_name = last_name
        self.first_name = first_name

    def introduce(self):
        return f"Я {self.first_name} {self.last_name}"


class Student(Person):
    def __init__(self, last_name, first_name, class_name):
        super().__init__(last_name, first_name)
        self.class_name = class_name

    def introduce(self):
        return f"{super().introduce()}, учень {self.class_name}"


class Teacher(Person):
    def __init__(self, last_name, first_name, subject):
        super().__init__(last_name, first_name)
        self.subject = subject

    def introduce(self):
        return f"{super().introduce()}, викладаю {self.subject}"
```

⚠ Виклик `super().introduce()` **усередині** перевизначеного методу — найкращий
момент теми. Дочірній клас не переписує роботу батька, а доповнює її.

**Крок 4. Поліморфізм**

Список із трьох різних об'єктів, один цикл. Далі — додати четвертий клас і

**Крок 5. Інкапсуляція**

Клас `BankAccount` із приватним балансом, `deposit`, `withdraw`,

ніж є.

Далі — спроба `account.__balance = 1000000` і висновок: баланс не змінився.

⚠ Питання, яке варто задати вголос: **де ми вже робили те саме в базі даних?**
`CHECK (Balance >= 0)` на дні 9 і транзакція з переказом на дні 16. Це та сама
ідея двома різними інструментами.
