### 1. Масив і список (5 хв)

**Масив** у класичному розумінні: елементи одного типу, розмір задано при
створенні, доступ за індексом.

**Список у Python** — гнучкіший:

```python
numbers = [3, 1, 4, 1, 5, 9, 2]
mixed = [1, "текст", True, 3.14]     # ⚠ так можна, але краще не треба
```

| | Класичний масив (C, Java) | Список Python |
|---|---|---|
| Типи елементів | один | будь-які |
| Розмір | фіксований | росте й зменшується сам |
| Швидкість доступу за індексом | висока | висока |

⚠ Скажи про `mixed`: змішувати типи технічно можна, але це майже завжди ознака
поганого проєктування. Список має містити однорідні речі — саме тому з ним
можна щось робити цілком.

Індексація — та сама, що в рядках (день 19):

```python
print(numbers[0])     # 3  — перший
print(numbers[-1])    # 2  — останній
print(numbers[1:4])   # [1, 4, 1] — зріз
print(len(numbers))   # 7
```

### 2. Методи списку (15 хв, головна частина)

Показуй кожен на проекторі, виводячи список після кожної дії — так видно, що
відбувається.

**Додати:**

```python
numbers.append(6)          # у кінець, один елемент
numbers += [7, 8]          # кілька одразу
numbers.insert(0, 99)      # на конкретне місце
```

**Видалити:**

```python
numbers.remove(1)     # перше входження ЗНАЧЕННЯ 1
numbers.pop(2)        # елемент за ІНДЕКСОМ 2, і повертає його
numbers.pop()         # останній
del numbers[0]        # за індексом
numbers.clear()       # усе
```

⚠⚠ **`remove` і `pop` — найпоширеніша плутанина уроку.** `remove(1)` шукає
**значення** 1. `pop(1)` бере елемент із **індексом** 1. Це різні речі, і
результат різний.

🖥 Покажи різницю на одному списку:

```python
a = [10, 20, 30, 40]
a.remove(20)      # шукає значення 20 → [10, 30, 40]

b = [10, 20, 30, 40]
b.pop(2)          # бере індекс 2 → [10, 20, 40]
```

**Знайти й перевірити:**

```python
print(numbers.index(4))     # індекс першого входження
print(4 in numbers)         # True / False
print(numbers.count(1))     # скільки разів трапляється
```

⚠ `index()` для елемента, якого немає, дає `ValueError`. Тому перед `index()`
зазвичай перевіряють через `in`. Це та сама обережність, що `IS NULL` у SQL.

**Змінити:**

```python
numbers[0] = 10
```

⚠ Порівняй із рядком: `text[0] = "X"` **не працює** — рядки незмінні. Списки
змінні. Це важлива різниця, і вона знадобиться на дні 22, коли з'явиться
кортеж.

**Перебрати** — це вже вміють із дня 20:

```python
for n in numbers:
    print(n)

for i in range(len(numbers)):    # коли потрібен саме індекс
    print(i, numbers[i])
```

### 3. Сортування в Python (7 хв)

```python
numbers.sort()                       # змінює сам список, нічого не повертає
sorted_numbers = sorted(numbers)     # повертає НОВИЙ список, оригінал цілий
```

| | `sort()` | `sorted()` |
|---|---|---|
| Що робить | сортує **на місці** | створює новий список |
| Оригінал | змінюється | не змінюється |
| Що повертає | `None` | новий список |

⚠⚠ **Пастка, на яку попадеться половина класу:**

```python
numbers = [3, 1, 2]
numbers = numbers.sort()      # ⚠ тепер numbers це None!
print(numbers)                # None
```

`sort()` повертає `None`, бо він уже змінив список. Покажи це на проекторі —
інакше на практиці буде десять однакових питань.

За спаданням і за ключем:

```python
numbers.sort(reverse=True)
words = ["груша", "яблуко", "слива"]
words.sort()                          # за алфавітом
words.sort(key=len)                   # за довжиною слова
```

### 4. Алгоритми сортування (13 хв)

Постав питання: **а як `sort()` це робить?** За ним стоїть алгоритм, і
алгоритми бувають різні.

#### Бульбашка (Bubble Sort) — розібрати докладно

🖐 **Спершу на дошці, без коду.** Напиши `[5, 2, 8, 1]` і проходь по парах:

```
5 2 8 1  →  порівняли 5 і 2, поміняли  →  2 5 8 1
2 5 8 1  →  5 і 8 стоять правильно     →  2 5 8 1
2 5 8 1  →  8 і 1, поміняли            →  2 5 1 8   ← найбільше "випливло" в кінець
```

Далі другий прохід, третій. Назва звідси: **великі елементи «випливають»
нагору, як бульбашки.**

```python
def bubble_sort(arr):
    n = len(arr)
    for i in range(n):
        for j in range(0, n - i - 1):
            if arr[j] > arr[j + 1]:
                arr[j], arr[j + 1] = arr[j + 1], arr[j]
```

⚠ Рядок `arr[j], arr[j+1] = arr[j+1], arr[j]` — обмін значеннями в один рядок.
У більшості мов для цього потрібна третя змінна. Покажи це окремо, воно
приємне й запам'ятовується.

**Складність O(n²)**: для 10 елементів ≈ 100 порівнянь, для 1000 ≈ мільйон.
Просто, але для великих даних непридатно.

#### Вибором (Selection Sort) — розібрати коротко

Ідея: знайти найменший елемент, поставити на перше місце; знайти найменший із
решти, поставити на друге; і так далі.

```python
def selection_sort(arr):
    n = len(arr)
    for i in range(n):
        min_idx = i
        for j in range(i + 1, n):
            if arr[j] < arr[min_idx]:
                min_idx = j
        arr[i], arr[min_idx] = arr[min_idx], arr[i]
```

Теж **O(n²)**, але переміщень робить менше за бульбашку.

#### Вставками, швидке, злиттям — оглядово

**Вставками (Insertion Sort)** — як розкладають карти в руці: беруть наступну й
вставляють на правильне місце серед уже впорядкованих. O(n²), але **дуже добре
працює на майже впорядкованих даних**.

**Швидке (Quick Sort)** — вибираємо «опорний» елемент, розкладаємо все менше
злива, більше справа, і **повторюємо те саме для кожної половини**:

```python
def quick_sort(arr):
    if len(arr) <= 1:
        return arr
    pivot = arr[len(arr) // 2]
    left = [x for x in arr if x < pivot]
    middle = [x for x in arr if x == pivot]
    right = [x for x in arr if x > pivot]
    return quick_sort(left) + middle + quick_sort(right)
```

⚠ Тут дві нові речі, кожну — одним реченням: **функція викликає сама себе**
(рекурсія) і **списковий вираз** `[x for x in arr if x < pivot]`. Не заглиблюйся,
але назви їх, бо учні побачать їх у коді.

Складність у середньому **O(n log n)** — для 1000 елементів ≈ 10 тисяч
порівнянь, а не мільйон. **У сто разів менше за бульбашку.**

**Злиттям (Merge Sort)** — ділимо навпіл, сортуємо половини, потім **зливаємо**
дві впорядковані половини в одну. Завжди O(n log n), але потребує додаткової
пам'яті.

Порівняльна таблиця — те, що варто дати під запис:

| Алгоритм | Складність | Коли доречний |
|---|---|---|
| Бульбашка | O(n²) | навчання; ніколи в реальному коді |
| Вибором | O(n²) | коли переміщення дорогі |
| Вставками | O(n²), на впорядкованих ≈ O(n) | малі або майже впорядковані дані |
| Швидке | O(n log n) у середньому | загальний випадок; те, що всередині `sort()` |
| Злиттям | O(n log n) завжди | коли потрібна гарантія й стабільність |

⚠ Скажи прямо: **у справжньому коді пишуть `sort()`**, а не свій алгоритм.
Знати алгоритми треба, щоб розуміти, чому одна програма чекає секунду, а
інша — годину. Це підготовка до дня 27, де буде складність алгоритмів.

**Крок 4. Статистика списку вручну**

Учень має знайти мінімум, максимум, суму й середнє **без** `min`, `max`, `sum` —
циклом. Потім порівняти з готовими функціями.

**Крок 5. Бульбашка своїми руками**

Головне завдання практики. Крім реалізації — **лічильник порівнянь**:

```python
def bubble_sort(arr):
    comparisons = 0
    n = len(arr)
    for i in range(n):
        for j in range(0, n - i - 1):
            comparisons += 1
            if arr[j] > arr[j + 1]:
                arr[j], arr[j + 1] = arr[j + 1], arr[j]
    return comparisons
```

Очікувані числа: для 10 елементів — 45 порівнянь, для 20 — 190, для 50 — 1225.

⚠ **Ключове спостереження:** список вдвічі довший — порівнянь **учетверо**
більше. Це і є O(n²) на власному досвіді, ще до того, як вони почують цю
