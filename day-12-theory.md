## Виклад

### 1. П'ять функцій (10 хв)

Агрегатна функція перетворює **багато рядків в одне значення**.

```sql
SELECT MIN(ListPrice) FROM SalesLT.Product;   -- найдешевший
SELECT MAX(ListPrice) FROM SalesLT.Product;   -- найдорожчий
SELECT SUM(ListPrice) FROM SalesLT.Product;   -- сума всіх цін
SELECT AVG(ListPrice) FROM SalesLT.Product;   -- середня ціна
SELECT COUNT(*)       FROM SalesLT.Product;   -- скільки рядків
```

Разом в одному запиті — так і роблять у звітах:

```sql
SELECT
    COUNT(*)        AS ProductCount,
    MIN(ListPrice)  AS Cheapest,
    MAX(ListPrice)  AS MostExpensive,
    AVG(ListPrice)  AS AveragePrice
FROM SalesLT.Product;
```

**`COUNT` має три різні форми, і це головна пастка розділу:**

| Форма | Що рахує |
|---|---|
| `COUNT(*)` | **усі рядки**, навіть із `NULL` |
| `COUNT(стовпець)` | рядки, де цей стовпець **не** `NULL` |
| `COUNT(DISTINCT стовпець)` | різні значення в стовпці |

🖥 Покажи три числа поспіль на проекторі:

```sql
SELECT COUNT(*), COUNT(Color), COUNT(DISTINCT Color) FROM SalesLT.Product;
```

Три різні числа з однієї таблиці. Учні, які на дні 8 бачили це на своїй базі,
тут отримують підтвердження.

### 2. Агрегати й NULL (6 хв)

Правило: **усі агрегатні функції, крім `COUNT(*)`, просто пропускають `NULL`.**

Наслідок, який варто розібрати уважно. У таблиці 10 товарів, у трьох вага не
вказана.

```sql
SELECT AVG(Weight) FROM SalesLT.Product;
```

Це середнє **по семи**, не по десяти. І це, як правило, правильно: усереднювати
невідоме безглуздо. Але знати про це треба, бо звіт покаже «середня вага» — а
насправді середню лише по тих, у кого вона є.

> Питання класу: **у школі 30 учнів, 25 склали тест, 5 не приходили. Яка
> середня оцінка класу?** Правильна відповідь — «залежить від того, що ми
> вважаємо за оцінку тих п'яти». `AVG` порахує по 25. Якщо тим п'ятьом
> поставити 0, середнє буде іншим. Це не питання SQL, це питання того, що ми
> хотіли дізнатись.

### 3. Підзапити (16 хв, головна частина)

**Підзапит** — запит усередині запиту. Виконується першим, а його результат
використовує зовнішній запит.

Почни з задачі, яку **не можна** розв'язати тим, що вже вивчили: «покажи товари,
дорожчі за середню ціну».

Спроба, яку зробить клас:

```sql
SELECT Name, ListPrice FROM SalesLT.Product
WHERE ListPrice > AVG(ListPrice);      -- ⚠ ПОМИЛКА
```

Помилка: `An aggregate may not appear in the WHERE clause`.

**Чому.** `WHERE` перевіряє **кожен рядок окремо**, коли решти рядків він ще не
бачив. А середнє неможливо знати, не подивившись на всі. Тобто в момент, коли
`WHERE` вирішує долю рядка, `AVG` ще не існує.

Розв'язок — порахувати середнє **окремим запитом**:

```sql
SELECT Name, ListPrice
FROM SalesLT.Product
WHERE ListPrice > (SELECT AVG(ListPrice) FROM SalesLT.Product);
```

Спосіб читати такий запит, який варто дати класу: **закрий підзапит пальцем і
уяви, що там просто число.** Внутрішній запит поверне, скажімо, 744 — і тоді
зовнішній це просто `WHERE ListPrice > 744`.

🖥 Покажи це буквально: виконай спершу тільки підзапит, отримай число, потім
підставь його руками замість підзапиту й отримай той самий результат.

Ще приклади:

```sql
-- найдорожчий товар (без ORDER BY і TOP)
SELECT Name, ListPrice FROM SalesLT.Product
WHERE ListPrice = (SELECT MAX(ListPrice) FROM SalesLT.Product);

-- товари з категорій, у назві яких є 'Bike'
SELECT Name FROM SalesLT.Product
WHERE ProductCategoryID IN (
    SELECT ProductCategoryID FROM SalesLT.ProductCategory
    WHERE Name LIKE '%Bike%'
);
```

Друга форма важлива: підзапит повернув **список**, тому зовні `IN`, а не `=`.

**Правило, яке варто виписати:**

| Підзапит повертає | Зовні пишемо |
|---|---|
| одне значення | `=`, `>`, `<` |
| список значень | `IN`, `NOT IN`, `ANY`, `ALL` |

⚠ `= (підзапит)`, який раптом повернув два рядки, дасть помилку `Subquery
returned more than 1 value`. Це найчастіша помилка на практиці.

Про ціну підзапитів скажи коротко: **корельований** підзапит (той, що
посилається на стовпець зовнішнього запиту) виконується для кожного рядка
окремо і може бути дуже повільним. Детально це не для 9 класу, але слово хай
почують.

### 4. ANY та ALL (9 хв)

Обидва працюють зі списком, який повернув підзапит.

- **`ANY`** — умова істинна, якщо виконується **хоч для одного** значення зі
  списку.
- **`ALL`** — істинна, якщо виконується **для всіх** значень.

```sql
-- дорожчі за ВСІ білі товари, тобто дорожчі за найдорожчий білий
SELECT Name, ListPrice FROM SalesLT.Product
WHERE ListPrice > ALL (SELECT ListPrice FROM SalesLT.Product WHERE Color = 'White');

-- дешевші ХОЧ ЗА ОДИН чорний товар, тобто дешевші за найдорожчий чорний
SELECT Name, ListPrice FROM SalesLT.Product
WHERE ListPrice < ANY (SELECT ListPrice FROM SalesLT.Product WHERE Color = 'Black');
```

⚠⚠ **Тут легко помилитись, і в багатьох посібниках це написано неправильно.**
Розберіть на дошці, повільно:

| Умова | Означає насправді |
|---|---|
| `x > ALL (список)` | `x` більше за **максимум** списку |
| `x < ALL (список)` | `x` менше за **мінімум** |
| `x > ANY (список)` | `x` більше за **мінімум** (досить перевищити хоч одне) |
| `x < ANY (список)` | `x` менше за **максимум** (досить бути меншим за хоч одне) |

Перевірка на числах, яку варто провести з класом. Список: `{10, 20, 30}`.

- `25 > ANY` → так (25 > 10). Отже `> ANY` це «більше за мінімум».
- `25 > ALL` → ні (25 не більше за 30). Отже `> ALL` це «більше за максимум».

Практичний висновок для учнів: **`ANY` і `ALL` майже завжди можна замінити на
`MAX`/`MIN` у підзапиті, і так зрозуміліше:**

```sql
-- те саме, що > ALL, але читається однозначно
WHERE ListPrice > (SELECT MAX(ListPrice) FROM SalesLT.Product WHERE Color = 'White')
```

Знати `ANY`/`ALL` треба, бо трапляються в чужому коді. Писати краще через
`MAX`/`MIN`.

---

## ⚠ Що піде не так

| Симптом | Причина | Що робити |
|---|---|---|
| `An aggregate may not appear in the WHERE clause` | `AVG` прямо у `WHERE` | підзапит; пояснення в розділі 3 |
| `Subquery returned more than 1 value` | `=` замість `IN` | таблиця «що повертає підзапит» |
| `AVG` дає не те, що чекали | пропущено `NULL` | розділ 2 |
| `COUNT(*)` і `COUNT(стовпець)` дають різне — учень вважає це збоєм | так і мусить бути | таблиця з розділу 1 |
| Плутають `ANY` і `ALL` | інтуїція обманює | перевірка на `{10,20,30}` |
| Підзапит виконується довго | корельований підзапит | згадати, що так буває; оптимізація — не для 9 класу |

## Урок 2 — практика: відповіді й критерії

### Відповіді

**Крок 1. Звіт по товарах**

```sql
SELECT COUNT(*) AS Кількість, MIN(ListPrice) AS Найдешевший,
       MAX(ListPrice) AS Найдорожчий, AVG(ListPrice) AS Середня,
       SUM(ListPrice) AS Сума
FROM SalesLT.Product;
```

`COUNT(*)` = 295. Мінімальна ціна — 2.29, максимальна — 3578.27.

**Крок 2. Три форми COUNT**

```sql
SELECT COUNT(*) AS Всього, COUNT(Color) AS ЗКольором,
       COUNT(DISTINCT Color) AS РізнихКольорів
FROM SalesLT.Product;
```

Числа різні. Друге менше за перше — бо в частини товарів `Color` дорівнює
`NULL`. Це відповідь на загадку дня 7 (крок із `NOT IN`) — обов'язково зв'яжи.

**Крок 3. Спроба, що не працює**

Учень мусить сам отримати помилку `An aggregate may not appear in the WHERE
clause` і **своїми словами** написати, чому. Очікується щось на кшталт: «`WHERE`
дивиться на один рядок, а середнє треба знати по всіх одразу».

Це головний крок практики. Хто написав це своїми словами — зрозумів підзапити.

**Крок 4. Підзапити**

```sql
-- 4.1 дорожчі за середню
SELECT Name, ListPrice FROM SalesLT.Product
WHERE ListPrice > (SELECT AVG(ListPrice) FROM SalesLT.Product);

-- 4.2 найдорожчий
SELECT Name, ListPrice FROM SalesLT.Product
WHERE ListPrice = (SELECT MAX(ListPrice) FROM SalesLT.Product);

-- 4.3 товари з "велосипедних" категорій
SELECT Name FROM SalesLT.Product
WHERE ProductCategoryID IN (
    SELECT ProductCategoryID FROM SalesLT.ProductCategory WHERE Name LIKE '%Bike%'
);
```

⚠ У 4.3 обов'язково `IN`, не `=`. Хто написав `=`, отримає `Subquery returned
more than 1 value` — і це корисна помилка, не підказуй заздалегідь.

**Крок 5. Заміна ANY/ALL на MAX/MIN**

Обидва варіанти мусять дати **однакову** кількість рядків. Якщо не дали — учень
переклав умову неправильно, і це саме те, що треба розібрати.
