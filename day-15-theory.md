## Виклад

### 1. Повторення: чому NULL псує звіти (5 хв)

Швидко, питаннями до класу:

- `NULL` — це **не** нуль і **не** порожній рядок, а «невідомо».
- Перевірка тільки через `IS NULL` / `IS NOT NULL`.
- **Будь-яка арифметика з `NULL` дає `NULL`.** `100 + NULL` = `NULL`.
- Склеювання тексту теж: `N'Іван' + NULL` = `NULL`.

Останнє й є практичною бідою. Згадай день 8, крок 1: учні виводили повне ім'я
через `FirstName + ' ' + LastName`, і в декого вийшов `NULL` замість імені —
через порожнє поле `Title` або друге ім'я. Один невідомий доданок псує весь
рядок.

Ось задача, яку розв'язує цей урок: **показати щось осмислене там, де значення
немає.**

### 2. ISNULL, COALESCE, NULLIF (13 хв, головна частина)

**`ISNULL(значення, заміна)`** — якщо перше `NULL`, повернути друге:

```sql
SELECT Name, ISNULL(Weight, 0) AS Вага FROM SalesLT.Product;
SELECT Name, ISNULL(Color, N'не вказано') AS Колір FROM SalesLT.Product;
```

**`COALESCE(значення1, значення2, значення3, …)`** — повертає **перше
не-`NULL`** зі списку. Тобто це `ISNULL` на будь-яку кількість аргументів:

```sql
SELECT COALESCE(MiddleName, FirstName, N'без імені') FROM SalesLT.Customer;
```

Читається як ланцюжок: «якщо є друге ім'я — покажи його; якщо ні — перше; якщо
й того немає — напиши `без імені`».

| | `ISNULL` | `COALESCE` |
|---|---|---|
| Аргументів | рівно 2 | скільки завгодно |
| Де працює | тільки SQL Server | **стандарт SQL**, працює всюди |
| Тип результату | за першим аргументом | за найширшим із аргументів |

⚠ Практична порада для учнів: **пиши `COALESCE`.** Він стандартний, тому запит
перенесеться в PostgreSQL чи MySQL без правок. `ISNULL` треба знати, бо в коді
під SQL Server його багато.

**`NULLIF(a, b)`** — робить навпаки: повертає `NULL`, якщо `a` дорівнює `b`.

```sql
SELECT Name, NULLIF(Color, 'White') AS Колір FROM SalesLT.Product;
```

Питання, яке варто задати: **навіщо взагалі створювати `NULL`, ми ж тільки-но
його прибирали?**

Два реальні застосування:

1. **Захист від ділення на нуль.** `100 / NULLIF(x, 0)` — якщо `x` дорівнює
   нулю, вийде `100 / NULL` = `NULL`, а не помилка. Звіт покаже порожню клітинку
   замість того, щоб упасти.
2. **Прибрати «сміттєві» значення з підрахунків.** Якщо в базі відсутність
   даних позначали текстом `'невідомо'`, то `AVG(NULLIF(поле, 'невідомо'))`
   виключить ці рядки з середнього — бо агрегати `NULL` пропускають (день 12).

Перше застосування варто показати на проекторі — воно наочне.

### 3. Збережені процедури (12 хв)

**Збережена процедура** — набір SQL-команд, який зберігається **в самій базі**
під іменем і викликається одним словом.

```sql
CREATE PROCEDURE SalesLT.GetOldProducts
AS
BEGIN
    SELECT * FROM SalesLT.Product
    WHERE SellEndDate IS NOT NULL;
END;
GO
```

Виклик:

```sql
EXEC SalesLT.GetOldProducts;
```

**З параметром** — ось де від процедур починається справжня користь:

```sql
CREATE PROCEDURE SalesLT.GetProductsByColor
    @Color NVARCHAR(15)
AS
BEGIN
    SELECT Name, ListPrice FROM SalesLT.Product
    WHERE Color = @Color;
END;
GO
```

```sql
EXEC SalesLT.GetProductsByColor 'Black';
EXEC SalesLT.GetProductsByColor @Color = 'White';   -- те саме, зрозуміліше
```

⚠ Параметри в T-SQL починаються з `@`. Це не примха: так база відрізняє змінну
від назви стовпця.

Кілька параметрів:

```sql
CREATE PROCEDURE SalesLT.FilterProducts
    @Color NVARCHAR(15),
    @Size NVARCHAR(5)
AS
BEGIN
    SELECT Name, Color, Size, ListPrice FROM SalesLT.Product
    WHERE Color = @Color AND Size = @Size;
END;
GO

EXEC SalesLT.FilterProducts @Color = 'Black', @Size = 'L';
```

Змінити наявну процедуру: `ALTER PROCEDURE` із тим самим текстом.
Видалити: `DROP PROCEDURE SalesLT.FilterProducts;`

⚠ `CREATE PROCEDURE` мусить бути першою командою в пакеті — тому перед нею й
після неї ставлять `GO`. Це та сама перепона, що з `CREATE SCHEMA` на дні 8.
Попередь заздалегідь.

### 4. Навіщо процедури (5 хв)

Три причини — і всі три варто прив'язати до того, що клас уже знає.

1. **Не повторювати код.** Складний звіт написаний один раз. Якщо в ньому
   знайшли помилку, правиться одне місце, а не десять програм, які його
   копіювали.
2. **Швидкість.** База зберігає готовий план виконання (день 10) і не будує
   його заново при кожному виклику.
3. **Безпека.** Користувачеві можна дати право **викликати процедуру**, не
   даючи прав на самі таблиці. Він отримає звіт і не зможе ні прочитати зайве,
   ні щось видалити.

Третя причина — найцінніша, і вона зшивається з днем 4: пам'ятаєш, чому
користувач не звертається до бази напряму? Ось процедура і є той «офіціант»,
через якого можна робити лише те, що передбачено.

> Питання класу: **у школі треба дати класним керівникам звіт по оцінках свого
> класу — і тільки свого. Як це зробити процедурою?** Процедура з параметром
> «номер класу», доступ лише на її виклик. Прямого доступу до таблиці оцінок у
> них немає.

## ⚠ Що піде не так

| Симптом | Причина | Що робити |
|---|---|---|
| `CREATE PROCEDURE must be the only statement in the batch` | немає `GO` | `GO` перед і після |
| `Must declare the scalar variable "@Color"` | забуто `@` або описка в імені | звірити з оголошенням |
| `There is already an object named …` | процедура вже існує | `ALTER PROCEDURE` або `DROP` спершу |
| `ISNULL` не спрацював, у результаті досі `NULL` | заміна теж `NULL`, або функція не там, де потрібно | подивитись, який саме стовпець порожній |
| Учень не бачить сенсу в `NULLIF` | немає прикладу | приклад із діленням на нуль, розділ 2 |
| Процедура створилась, але її не видно в дереві | не оновлено | `Refresh` на `Programmability → Stored Procedures` |

## Урок 2 — практика: відповіді й критерії

Учнівський файл: `day-15-practice.md`. Файл здачі — `day15.sql`.

### Відповіді

**Крок 1. NULL псує звіт**

```sql
SELECT FirstName + ' ' + MiddleName + ' ' + LastName AS FullName
FROM SalesLT.Customer;
```

У багатьох рядках буде `NULL`, бо `MiddleName` не заповнено. Виправлення:

```sql
SELECT FirstName + ' ' + ISNULL(MiddleName + ' ', '') + LastName AS FullName
FROM SalesLT.Customer;
```

⚠ Тонкість, яку варто розібрати з тими, хто дійде: пробіл ставлять **усередину**
`ISNULL`, разом із другим ім'ям. Інакше в рядках без другого імені з'явиться
подвійний пробіл. Хто це помітив сам — 12 балів.

**Крок 2. ISNULL і COALESCE**

```sql
SELECT Name, ISNULL(Color, N'не вказано') AS Колір,
       ISNULL(Weight, 0) AS Вага
FROM SalesLT.Product;

SELECT COALESCE(MiddleName, FirstName, N'невідомо') FROM SalesLT.Customer;
```

Питання про різницю: `COALESCE` бере скільки завгодно аргументів і є стандартом
SQL; `ISNULL` — рівно два й лише в SQL Server.

**Крок 3. NULLIF і ділення на нуль**

```sql
SELECT 100 / 0;                    -- Divide by zero error encountered
SELECT 100 / NULLIF(0, 0);         -- NULL, без помилки
```

Обов'язковий висновок: `NULLIF` перетворив аварію на порожню клітинку.

**Крок 4. Процедура без параметрів**

```sql
CREATE PROCEDURE SalesLT.ExpensiveProducts
AS
BEGIN
    SELECT Name, ListPrice FROM SalesLT.Product
    WHERE ListPrice > 1000
    ORDER BY ListPrice DESC;
END;
GO

EXEC SalesLT.ExpensiveProducts;
```

**Крок 5. Процедура з параметром**

```sql
CREATE PROCEDURE SalesLT.ProductsByPrice
    @MinPrice DECIMAL(10,2)
AS
BEGIN
    SELECT Name, ListPrice, ISNULL(Color, N'не вказано') AS Колір
    FROM SalesLT.Product
    WHERE ListPrice >= @MinPrice
    ORDER BY ListPrice DESC;
END;
GO

EXEC SalesLT.ProductsByPrice 2000;
EXEC SalesLT.ProductsByPrice @MinPrice = 100;
```

**Крок 6. Два параметри**

Очікується процедура з `@Color` і `@MinPrice`, зокрема виклик, який нічого не
поверне (наприклад червоні дорожчі за 3000) — і учень мусить зрозуміти, що
порожній результат це не помилка процедури.
