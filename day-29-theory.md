### 2. Підключення й перший запит (12 хв)

```
pip install pyodbc
```

```python
import pyodbc

conn = pyodbc.connect(
    "Driver={ODBC Driver 17 for SQL Server};"
    "Server=localhost\\SQLEXPRESS;"
    "Database=AdventureWorksLT;"
    "Trusted_Connection=yes;"
)

cursor = conn.cursor()
print("Підключення успішне!")
```

Розбір рядка підключення — кожен рядок пояснити:

| Частина | Що означає |
|---|---|
| `Driver=...` | яким драйвером говорити із сервером |
| `Server=localhost\\SQLEXPRESS` | де сервер. **Дві похилі**, бо в Python `\` — службовий символ |
| `Database=...` | до якої бази |
| `Trusted_Connection=yes` | вхід під обліковим записом Windows — той самий, що в SSMS |

⚠ **Ім'я бази мусить збігатися з тим, що в дереві SSMS.** Залежно від того, як
відновлювали, вона може називатись `AdventureWorksLT` або `AdventureWorksLT2019`.
Скажи класу подивитись у себе.

**Перший запит:**

```python
cursor.execute("""
    SELECT TOP 10 CustomerID, FirstName, LastName, EmailAddress
    FROM SalesLT.Customer
    ORDER BY CustomerID
""")

for row in cursor.fetchall():
    print(f"{row.CustomerID}: {row.FirstName} {row.LastName} — {row.EmailAddress}")
```

Три речі, які тут варто назвати:

1. **Потрійні лапки** для багаторядкового SQL — так запит читається як у SSMS.
   Це той самий синтаксис, що на дні 19.
2. `fetchall()` — усі рядки списком. `fetchone()` — один рядок.
3. `row.CustomerID` — звернення до стовпця **за іменем**. Можна й `row[0]`, але
   за іменем зрозуміліше.

⚠ Зв'яжи з днем 25: `cursor` — це **ітератор**. По ньому можна йти напряму:

```python
for row in cursor:
    print(row.FirstName)
```

Так рядки беруться по одному, і мільйон записів не завантажується в пам'ять.
Це рівно та сама ідея, що `range` проти `list(range)`.

### 3. Параметри через `?` (10 хв — найважливіше)

Спершу покажи, як **не треба**:

```python
customer_id = input("ID клієнта: ")
cursor.execute("SELECT * FROM SalesLT.Customer WHERE CustomerID = " + customer_id)
```

Питання класу: **що станеться, якщо користувач замість числа введе
`1 OR 1=1`?** Запит перетвориться на:

```sql
SELECT * FROM SalesLT.Customer WHERE CustomerID = 1 OR 1=1
```

Умова істинна для **всіх** рядків — і програма видасть усю таблицю клієнтів.

А якщо ввести `1; DROP TABLE SalesLT.Customer`? Це називається **SQL-ін'єкція**,
і це одна з найпоширеніших атак на застосунки у світі.

⚠ Зв'яжи з днем 3: там була таблиця видів загроз. Тепер учні бачать, як така
атака виглядає в коді.

**Правильно — через `?`:**

```python
customer_id = int(input("ID клієнта: "))

cursor.execute("""
    SELECT SalesOrderID, OrderDate, TotalDue
    FROM SalesLT.SalesOrderHeader
    WHERE CustomerID = ?
""", customer_id)

orders = cursor.fetchall()
if orders:
    for order in orders:
        print(f"Замовлення {order.SalesOrderID} | {order.OrderDate} | {order.TotalDue}")
else:
    print("Цей клієнт ще не має замовлень.")
```

Чому `?` безпечний: значення передається **окремо від тексту запиту**. База
розуміє його як **дані**, а не як частину команди. Що б туди не написали, воно
залишиться просто рядком для порівняння.

⚠ **Правило під запис: значення в запит підставляються тільки через `?`.
Ніколи склеюванням.** Це головне, що варто винести з дня 29.

Кілька параметрів — по порядку:

```python
cursor.execute("""
    SELECT Name, ListPrice FROM SalesLT.Product
    WHERE Color = ? AND ListPrice > ?
""", color, min_price)
```

### 4. INSERT, UPDATE, DELETE і commit (8 хв)

```python
cursor.execute("""
    INSERT INTO Club.Members (ID, LastName, FirstName, IsActive)
    VALUES (?, ?, ?, ?)
""", 10, "Іваненко", "Богдан", 1)

conn.commit()          # ⚠ БЕЗ ЦЬОГО ЗМІН НЕ БУДЕ
```

⚠⚠ **`commit()` — найчастіша помилка дня.** Без нього програма відпрацює,
нічого не скаже, а в базі нічого не з'явиться. Учень перевірить у SSMS і не
зрозуміє, що сталось.

Зв'яжи з днем 16: це буквально `COMMIT TRANSACTION`. `pyodbc` за замовчуванням
відкриває транзакцію сам, і поки немає `commit()`, зміни не зафіксовані. А
якщо програма закриється — відбудеться `ROLLBACK`.

```python
cursor.execute("UPDATE Club.Members SET IsActive = ? WHERE ID = ?", 0, 10)
conn.commit()

cursor.execute("DELETE FROM Club.Members WHERE ID = ?", 10)
conn.commit()
```

⚠ **Правило дня 10 діє й тут:** перед `DELETE` або `UPDATE` спершу зроби
`SELECT` із тим самим `WHERE` і подивись, скільки рядків зачепиться. У Python це
навіть зручніше:

```python
cursor.execute("SELECT COUNT(*) FROM Club.Members WHERE IsActive = ?", 0)
count = cursor.fetchone()[0]
answer = input(f"Буде видалено {count} записів. Продовжити? (так/ні) ")
if answer == "так":
    ...
```

⚠ **Практику з `INSERT`/`UPDATE`/`DELETE` робимо на власній базі учня** — тій,
яку він створив на тематичній роботі. Не на `AdventureWorksLT`: там у таблиці
`Customer` є обов'язкові стовпці (`PasswordHash`, `PasswordSalt`), без яких
`INSERT` просто не пройде, а `DELETE` заблокують зовнішні ключі. Це не
навчальна проблема, а зайва морока.

### 5. Розділення на файли (7 хв)

Одна довга програма нечитабельна. Розкладаємо:

```
project/
├── database.py    # підключення
├── customer.py    # робота з клієнтами
├── orders.py      # робота з замовленнями
└── main.py        # меню й запуск
```

**`database.py`:**

```python
import pyodbc

def get_connection():
    return pyodbc.connect(
        "Driver={ODBC Driver 17 for SQL Server};"
        "Server=localhost\\SQLEXPRESS;"
        "Database=AdventureWorksLT;"
        "Trusted_Connection=yes;"
    )
```

**`customer.py`:**

```python
from database import get_connection

def list_customers(limit=10):
    conn = get_connection()
    cursor = conn.cursor()
    cursor.execute("""
        SELECT TOP (?) CustomerID, FirstName, LastName
        FROM SalesLT.Customer ORDER BY CustomerID
    """, limit)
    rows = cursor.fetchall()
    conn.close()
    return rows
```

**`main.py`:**

```python
from customer import list_customers

def main():
    for c in list_customers():
        print(f"{c.CustomerID}: {c.FirstName} {c.LastName}")

if __name__ == "__main__":
    main()
```

⚠ Тут сходяться два попередні дні: **власний модуль** із дня 28 і `if __name__
== "__main__"` звідти ж.

Навіщо розділяти — три причини, ті самі, що для функцій на дні 23:

1. рядок підключення в **одному** місці; змінився сервер — правиш один файл
2. кожен файл про одне
3. функцію з `customer.py` можна взяти в іншу програму

⚠ І одна деталь про `close()`: з'єднання треба закривати. Надійніше через
`with`:

```python
with get_connection() as conn:
    cursor = conn.cursor()
    ...
```

Але скажи чесно: у `pyodbc` вихід із `with` робить `commit`, а **не** закриває
з'єднання. Тому в навчальних програмах простіше явно писати `conn.close()`.

## ⚠ Що піде не так

| Симптом | Причина | Що робити |
|---|---|---|
| `Data source name not found and no default driver specified` | немає ODBC-драйвера | встановити `ODBC Driver 17/18 for SQL Server`; перевірити назву у вкладці `Драйвери` |
| `Login timeout expired` | сервер не запущений або не те ім'я | `services.msc` → `SQL Server (SQLEXPRESS)`; звірити ім'я з SSMS |
| `Cannot open database ... requested by the login` | не та назва бази | подивитись у дереві SSMS |
| `Invalid object name 'Customer'` | забули схему | `SalesLT.Customer` |
| Дані «не збереглись» | немає `conn.commit()` | найчастіша помилка дня |
| `The SQL contains 1 parameter markers, but 0 parameters were supplied` | забули передати значення для `?` | звірити кількість |
| Українські літери «кракозябрами» | старий драйвер або `VARCHAR` замість `NVARCHAR` | драйвер 17+, `N'текст'` у базі |
| `ModuleNotFoundError: No module named 'pyodbc'` | не встановлено | `python -m pip install pyodbc` |

### Що мусить бути в роботі

### Ключові моменти оцінювання

⚠ **Крок 3 — головний.** Учень має спробувати склеювання рядків, ввести
`1 OR 1=1`, побачити всю таблицю, а потім переписати через `?` і переконатись,
що атака більше не працює.

Питання, на яке має бути відповідь письмово: **чому `?` захищає?** Очікується
щось на кшталт «значення передається окремо від тексту запиту, і база
сприймає його як дані, а не як команду».

⚠ **Крок 5 — `commit()`.** Обов'язково: спершу зробити `INSERT` **без**
`commit`, перевірити в SSMS, що рядка немає, потім додати `commit` і перевірити
знову. Без цього досвіду учні писатимуть програми, які «мовчки нічого не
роблять».

⚠ **Крок 7 — розділення на файли.** Мінімум: `database.py` із `get_connection()`
і ще один файл із функціями. Перевіряй, що рядок підключення **не
продубльовано**.
