## Виклад

### 1. Постановка (5 хв)

Питання класу: **ви дванадцять уроків писали запити в SQL Server. Якщо на
роботі дадуть PostgreSQL — доведеться вчитись заново?**

Відповідь, до якої треба вести весь урок: **приблизно 85% того, що ви знаєте,
працює всюди без правок.** `SELECT`, `WHERE`, `JOIN`, `GROUP BY`, `HAVING`,
`INSERT`, `UPDATE`, `DELETE`, обмеження, транзакції — це стандарт SQL.

Решта 15% — діалект: обмеження кількості рядків, робота з датами, типи для
тексту, процедурна мова. Саме про них цей урок.

### 2. SQL Server (8 хв)

Розробник — **Microsoft**. Реляційна, комерційна (є безкоштовна Express, яку ми
й ставили на дні 5).

**Де застосовують:** корпоративні системи на Windows, бізнес-аналітика,
інтеграція з Azure, .NET, Excel.

**Діалект — T-SQL (Transact-SQL).** Додає до стандарту процедурні можливості:
змінні, цикли, умови.

```sql
DECLARE @UserName NVARCHAR(50);
SET @UserName = N'Іваненко';
SELECT * FROM Users WHERE LastName = @UserName;
```

Що ви вже бачили саме з T-SQL: `TOP`, `NVARCHAR`, `ISNULL`, `GETDATE()`,
`SYSDATETIME()`, `@параметри` в процедурах, `#тимчасові` таблиці.

### 3. PostgreSQL (8 хв)

**Відкритий код**, розвивається спільнотою. Репутація найсуворішого щодо
стандарту SQL і найрозширюванішого.

**Де застосовують:** складні застосунки, наукові дані, геопросторові задачі
(розширення **PostGIS** — карти, маршрути, координати), стартапи (бо
безкоштовна).

**Діалект — PL/pgSQL.** Особливості, які варто назвати:

- рекурсивні запити `WITH RECURSIVE` — обхід дерев та ієрархій
- багаті типи: масиви, `JSON`, `JSONB`, геопросторові
- функції можна писати навіть на Python

Приклад рекурсивного запиту (не розбирати детально, показати як «на що це схоже»):

```sql
WITH RECURSIVE EmployeeHierarchy AS (
    SELECT EmployeeID, ManagerID, 1 AS Level
    FROM Employees WHERE ManagerID IS NULL
    UNION ALL
    SELECT e.EmployeeID, e.ManagerID, eh.Level + 1
    FROM Employees e
    INNER JOIN EmployeeHierarchy eh ON e.ManagerID = eh.EmployeeID
)
SELECT * FROM EmployeeHierarchy;
```

⚠ Скажи класу, що вони тут уже все розпізнають: `SELECT`, `UNION ALL`,
`INNER JOIN`, `IS NULL`. Незнайоме лише слово `RECURSIVE`. Це найкраща
ілюстрація тези з розділу 1.

### 4. MySQL (6 хв)

**Відкритий код**, зараз належить Oracle. Найпоширеніша в вебі.

**Де застосовують:** сайти, WordPress, Joomla, Drupal, блоги, форуми,
інтернет-магазини, невеликі проєкти.

Особливості:

- **різні механізми зберігання**: `InnoDB` (транзакції й зовнішні ключі) і
  `MyISAM` (швидке читання, без транзакцій)
- процедурні можливості слабші, ніж у решти
- проста в установці й адмініструванні — тому й обирають для малих проєктів

```sql
SELECT * FROM Products ORDER BY Price DESC LIMIT 10;
```

⚠ `LIMIT 10` замість `TOP 10`. Це та сама відмінність, яку клас бачив на дні 7.

### 5. Oracle Database (6 хв)

Комерційна, дорога, найпотужніша за можливостями масштабування.

**Де застосовують:** банки, державні системи, великі корпорації —
там, де обсяги величезні, а простій неприпустимий.

**Діалект — PL/SQL.**

```sql
DECLARE
    v_salary NUMBER(8,2);
BEGIN
    SELECT salary INTO v_salary FROM employees WHERE employee_id = 100;
    DBMS_OUTPUT.PUT_LINE('Salary is: ' || v_salary);
END;
```

Тут відмінностей більше: `NUMBER` замість `INT`, `||` для склеювання тексту
замість `+`, `DBMS_OUTPUT.PUT_LINE` замість `PRINT`, обов'язковий блок
`BEGIN … END`.

### 6. Таблиця відмінностей (8 хв, головна частина)

Це те, що учні перепишуть і що знадобиться на практиці.

| Задача | SQL Server | PostgreSQL / MySQL / SQLite | Oracle |
|---|---|---|---|
| Перші N рядків | `SELECT TOP 10 …` | `… LIMIT 10` | `… FETCH FIRST 10 ROWS ONLY` |
| Склеїти текст | `'a' + 'b'` | `'a' \|\| 'b'` | `'a' \|\| 'b'` |
| Замінити `NULL` | `ISNULL(x, 0)` | `COALESCE(x, 0)` | `NVL(x, 0)` |
| Текст будь-якою мовою | `NVARCHAR(50)` | `VARCHAR(50)` (уже Unicode) | `NVARCHAR2(50)` |
| Поточна дата й час | `GETDATE()` | `NOW()` | `SYSDATE` |
| Автономер | `IDENTITY` | `SERIAL` / `AUTO_INCREMENT` | `SEQUENCE` |
| Процедурна мова | T-SQL | PL/pgSQL | PL/SQL |

⚠ **Одне спостереження, яке варто підкреслити:** `COALESCE` є в **усіх** трьох
стовпцях. Ось чому на дні 15 радилось писати `COALESCE`, а не `ISNULL` — воно
стандартне.

**Як обирають СКБД** — коротко, це буде питанням практики:

| Задача | Розумний вибір | Чому |
|---|---|---|
| Сайт школи на WordPress | MySQL | WordPress під неї й написаний |
| Корпоративна система на Windows і .NET | SQL Server | інтеграція |
| Стартап без грошей, складна логіка | PostgreSQL | безкоштовна й потужна |
| Банк на 10 мільйонів клієнтів | Oracle або SQL Server | масштаб і підтримка |
| Застосунок на телефоні | SQLite | усередині телефона, серверa не треба |

> Питання класу: **чому не всі просто беруть Oracle, якщо вона найпотужніша?**
> Ціна ліцензій, складність адміністрування, потреба в окремому спеціалісті.
> Найпотужніший інструмент не є найкращим для кожної задачі — це загальна
> думка, яку варто донести не лише про бази.

## Урок 2 — практика: відповіді й критерії

Учнівський файл: `day-17-practice.md`. Здача — документ або `day17.md`.

### Крок 1. Переклад запитів

| Запит у T-SQL | PostgreSQL/MySQL |
|---|---|
| `SELECT TOP 5 * FROM Product ORDER BY Price DESC` | `SELECT * FROM Product ORDER BY Price DESC LIMIT 5` |
| `SELECT FirstName + ' ' + LastName FROM Customer` | `SELECT FirstName \|\| ' ' \|\| LastName FROM Customer` |
| `SELECT ISNULL(Color, 'нема') FROM Product` | `SELECT COALESCE(Color, 'нема') FROM Product` |
| `SELECT GETDATE()` | `SELECT NOW()` |

⚠ Найцікавіший випадок — третій рядок: `COALESCE` працює **в обох**, тому
перекладати нічого не треба. Учень, який це помітив, зрозумів головну думку
уроку.

### Крок 2. Запуск у чужій СКБД

На db-fiddle.com або sqliteonline.com учень виконує три запити й бачить, що
базовий SQL працює без правок, а `TOP` — ні.

Очікувана помилка на `SELECT TOP 5`: `syntax error at or near "5"` (PostgreSQL)
або аналогічна. Хай скопіює текст.

### Крок 3. Вибір СКБД під задачу

Задачі в учнівському файлі. Приймається будь-який вибір із обґрунтуванням, але
є очевидно кращі:

| Задача | Очікуване | Що мусить бути в обґрунтуванні |
|---|---|---|
| Сайт-візитівка школи | MySQL | під WordPress; безкоштовна; проста |
| Застосунок «список покупок» на телефон | SQLite | немає сервера; база у файлі на пристрої |
| Система обліку в лікарні (Windows-мережа) | SQL Server | транзакції, інтеграція, підтримка |
| Стартап-карти маршрутів | PostgreSQL + PostGIS | геопросторові дані |
| Кеш для сайту з мільйоном відвідувачів | Redis (не реляційна!) | швидкість, дані в пам'яті |

⚠ Останній рядок — пастка на користь дня 18. Учень, який відповів «жодна з
чотирьох, тут треба щось інше», уже готовий до наступного уроку.

### Крок 4. Дослідження

Учень сам шукає в інтернеті, як у PostgreSQL робиться дві речі, які він робив на
SQL Server. Оцінюється не результат, а те, чи навчився шукати: правильний
запит у пошук — це `postgresql <що треба зробити>`, а не назва T-SQL-функції.

### Крок 5. Паперове порівняння

Таблиця з чотирьох СКБД: розробник, ліцензія, типова сфера, діалект, одна
особливість. Це страховка, якщо інтернет не працює — тоді цей крок стає
головним і робиться детальніше.
