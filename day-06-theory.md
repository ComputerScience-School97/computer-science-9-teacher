## Виклад

### 1. Що таке SQL (8 хв)

**SQL (Structured Query Language)** — мова для роботи з реляційними базами.

Головна її властивість, з якої варто починати: **SQL декларативна.** Ти
описуєш, **що** хочеш отримати, а не **як** це знайти.

Порівняння, яке варто дати на дошці:

```
Імперативно (як у Python):
  візьми список товарів
  для кожного товару:
      якщо ціна > 100:
          додай його у відповідь

Декларативно (SQL):
  SELECT Name FROM SalesLT.Product WHERE ListPrice > 100
```

У другому випадку **ти не сказав, як шукати** — перебирати все чи йти за
індексом. Це вирішить сама база, і зазвичай вирішить краще за тебе.

> Питання класу: **чи це добре — не керувати тим, як виконується запит?**
> Здебільшого так: база знає про свої дані більше. Але саме тому іноді запит
> раптом стає повільним, і тоді програміст мусить розуміти, що там усередині —
> про це буде день 10, індекси.

Що ще вміє SQL: фільтрувати (`WHERE`), сортувати (`ORDER BY`), групувати
(`GROUP BY`), з'єднувати таблиці (`JOIN`), агрегувати (`SUM`, `COUNT`),
керувати транзакціями й правами доступу.

### 2. Історія і діалекти (5 хв)

- **1970** — Едгар Кодд, IBM, стаття про реляційну модель.
- Далі IBM робить мову запитів **SEQUEL** для системи System R. Через
  юридичний конфлікт із назвою її скорочують до **SQL**.
- **1986** — стандарт ANSI, **1987** — ISO.
- Кожен виробник додав своє. Так з'явились **діалекти**:

| Діалект | Чий | Особливість |
|---|---|---|
| **T-SQL** | Microsoft SQL Server | процедури, змінні, керуючі конструкції — **з ним працюємо ми** |
| PL/SQL | Oracle | процедурна мова всередині SQL |
| PL/pgSQL | PostgreSQL | своя процедурна мова, багато типів даних |

Практичний висновок для учнів: **80% того, що ми вивчимо, працює в будь-якій
базі.** Решта — особливості T-SQL, і про різницю поговоримо на дні 17.

### 3. Дев'ять базових команд (17 хв, головна частина)

Кожну — на проекторі, живцем. Учні дивляться, не друкують; друкувати будуть на
уроці 2.

**SELECT + FROM** — вибрати дані:

```sql
SELECT ProductID, Name FROM SalesLT.Product;
```

`SELECT *` бере всі стовпці. ⚠ Скажи одразу: `*` годиться, щоб подивитись, і
не годиться в справжній програмі — тягне зайве й ламається, коли в таблиці
з'являється новий стовпець.

**WHERE** — фільтр:

```sql
SELECT Name, ListPrice FROM SalesLT.Product WHERE ListPrice > 100;
```

**INSERT INTO** — додати рядок:

```sql
INSERT INTO SalesLT.ProductCategory (Name) VALUES ('Тестова категорія');
```

**UPDATE** — змінити:

```sql
UPDATE SalesLT.ProductCategory
SET Name = 'Оновлена категорія'
WHERE Name = 'Тестова категорія';
```

**DELETE** — видалити рядки:

```sql
DELETE FROM SalesLT.ProductCategory WHERE Name = 'Оновлена категорія';
```

⚠⚠ **Покажи це вголос і напиши на дошці:** `UPDATE` і `DELETE` **без `WHERE`
зміняють або видаляють усю таблицю**. Це найдорожча помилка, яку взагалі можна
зробити в SQL, і роблять її дорослі люди на робочих базах. Правило: спершу
пиши `WHERE`, потім усе інше.

**CREATE TABLE** — створити таблицю:

```sql
CREATE TABLE SalesLT.SalesPerson (
    ID INT PRIMARY KEY,
    FirstName NVARCHAR(50),
    LastName NVARCHAR(50),
    PhoneNumber NVARCHAR(50)
);
```

`NVARCHAR` — текст із підтримкою будь-яких мов. ⚠ Для української завжди
`NVARCHAR`, не `VARCHAR`.

**ALTER TABLE** — змінити структуру:

```sql
ALTER TABLE SalesLT.SalesPerson ADD Email NVARCHAR(100);
```

**DROP TABLE** — видалити таблицю разом зі структурою:

```sql
DROP TABLE SalesLT.SalesPerson;
```

Різниця `DELETE` і `DROP`: `DELETE` прибирає рядки, таблиця лишається;
`DROP` прибирає саму таблицю.

### 4. Схеми (8 хв)

**Схема** — логічний контейнер для об'єктів бази: таблиць, представлень,
процедур. Саме тому в нашій базі всі таблиці звуться `SalesLT.Product`,
`SalesLT.Customer` — `SalesLT` це схема, `Product` це таблиця.

Навіщо:

1. **Порядок.** У великій базі схеми `Sales`, `HR`, `Finance` — і одразу видно,
   що чиє.
2. **Права доступу.** Бухгалтерії дають доступ до схеми `Finance` і не дають до
   `HR`.
3. **Немає конфлікту імен.** Може бути `HR.Employees` і `Sales.Employees` —
   різні таблиці з однією назвою.
4. **Обслуговування.** Об'єкти переносять між схемами, не ламаючи решту.

```sql
CREATE SCHEMA Shop;
CREATE TABLE Shop.Orders (
    OrderID INT PRIMARY KEY,
    OrderDate DATE
);
```

⚠ Якщо схему не вказати, SQL Server підставить схему за замовчуванням —
зазвичай `dbo`. Тобто `CREATE TABLE Orders` створить `dbo.Orders`. Учні
натраплять на це, коли не зможуть знайти свою таблицю в дереві — вона просто
лежить в іншій папці.

### 5. 🖥 Відновлення бази з файлу (5 хв)

Покажи на проекторі повністю, крок за кроком — на практиці учні це повторять:

`Object Explorer` → права кнопка на `Databases` → `Restore Database…` →
`Device` → `…` → `Add` → вибрати `AdventureWorksLT.bak` → `OK` → `OK`.

⚠ Файл `.bak` мусить лежати там, куди **служба SQL Server** має доступ. Тека
`Завантаження` користувача часто не підходить. Надійно: створити `C:\sqlbak\` і
покласти файл туди. Скажи це до того, як 25 людей побачать помилку доступу.

## ⚠ Що піде не так

| Симптом | Причина | Що робити |
|---|---|---|
| `Invalid object name 'Product'` | забуто схему | `SalesLT.Product` |
| `Operating system error 5 (Access denied)` при відновленні | файл `.bak` у теці, недоступній службі | перекласти в `C:\sqlbak\` |
| Замість української в тексті знаки питання | `VARCHAR` замість `NVARCHAR`, або забуто `N'текст'` | `NVARCHAR` і `N'Іваненко'` |
| Виконався не той запит | курсор стояв не там | виділити запит мишкою, `Ctrl+Shift+E` |
| Хтось видалив дані з демо-бази | `DELETE` без `WHERE` | відновити базу з `.bak` заново; це двохвилинна справа, тому не драматизуй |

### Крок 2. Огляд структури

Учень виписує таблиці й здогадується, що в них. Очікуване:

| Таблиця | Що в ній |
|---|---|
| `Customer` | клієнти |
| `Address` | адреси |
| `CustomerAddress` | зв'язок «клієнт ↔ адреса» |
| `Product` | товари |
| `ProductCategory` | категорії товарів |
| `ProductModel` | моделі товарів |
| `SalesOrderHeader` | замовлення |
| `SalesOrderDetail` | позиції замовлень |

⚠ Найцінніше питання цього кроку: **навіщо потрібна таблиця
`CustomerAddress`, якщо є `Customer` і `Address`?** Бо в одного клієнта може
бути кілька адрес, а за однією адресою — кілька клієнтів. Це та сама думка, що
на дні 5 із гуртками. Хто відповів сам — розуміє реляційну модель.

### Крок 3. Перші SELECT

Правильні варіанти:

```sql
SELECT * FROM SalesLT.Product;                          -- 295 рядків
SELECT Name, ListPrice FROM SalesLT.Product;
SELECT Name, ListPrice FROM SalesLT.Product WHERE ListPrice > 1000;
SELECT FirstName, LastName FROM SalesLT.Customer WHERE LastName = 'Adams';
SELECT Name, Color, ListPrice FROM SalesLT.Product WHERE Color = 'Black';
```

> ⚠ Числа рядків тут і далі — для стандартної `AdventureWorksLT`. Прогони
> запити на своїй копії перед уроком.

### Крок 4. Своя схема й таблиця

```sql
CREATE SCHEMA School;

CREATE TABLE School.Students (
    ID INT PRIMARY KEY,
    FirstName NVARCHAR(50),
    LastName NVARCHAR(50),
    ClassName NVARCHAR(10)
);

INSERT INTO School.Students (ID, FirstName, LastName, ClassName)
VALUES (1, N'Богдан', N'Іваненко', N'9-А');

ALTER TABLE School.Students ADD Email NVARCHAR(100);

SELECT * FROM School.Students;
```

⚠ Учень, який вставив українське прізвище **без `N`** перед лапками, побачить
знаки питання. Це найкращий можливий момент, щоб назавжди запам'ятати, для чого
`N`. Не підказуй заздалегідь — дай натрапити.

### Крок 5. DELETE проти DROP

Послідовність: `DELETE` (таблиця лишилась, рядків нема) → `SELECT` (порожньо,
але працює) → `DROP` → `SELECT` → помилка `Invalid object name`.

Обов'язковий висновок письмово: **`DELETE` прибирає дані, `DROP` прибирає саму
таблицю.**
