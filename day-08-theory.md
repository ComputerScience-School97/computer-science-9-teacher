## Виклад

### 1. Псевдоніми (8 хв)

**Псевдонім (alias)** — тимчасове ім'я для стовпця або таблиці в межах запиту.

```sql
SELECT FirstName + ' ' + LastName AS FullName
FROM SalesLT.Customer AS c
WHERE c.Title IS NOT NULL;
```

Три речі, які тут показані одразу: обчислений стовпець, псевдонім для нього,
псевдонім для таблиці.

Навіщо це потрібно:

1. **Обчислені стовпці** мусять якось називатись. Без `AS` заголовок буде
   порожній або `(No column name)`.
2. **Короткі імена таблиць** — без них запит на три таблиці неможливо читати
   (побачимо на дні 13).
3. **Читабельність.** `ListPrice * 0.9 AS DiscountedPrice` зрозуміло, а
   `ListPrice * 0.9` без імені — ні.

Слово `AS` можна не писати, але краще писати: `SELECT Name FullName` виглядає
як помилка.

### 2. Сортування (9 хв)

```sql
-- за зростанням (ASC — за замовчуванням, можна не писати)
SELECT * FROM SalesLT.Product ORDER BY ListPrice ASC;

-- за спаданням
SELECT * FROM SalesLT.Product ORDER BY Name DESC;

-- за двома стовпцями: спершу категорія, у межах категорії — ціна вниз
SELECT * FROM SalesLT.Product ORDER BY ProductCategoryID ASC, ListPrice DESC;

-- за обчисленим значенням
SELECT Name, ListPrice * 0.9 AS DiscountedPrice
FROM SalesLT.Product
ORDER BY DiscountedPrice ASC;
```

⚠ Сортування за двома стовпцями варто розібрати на дошці, бо його плутають.
Другий стовпець працює **тільки в межах однакових значень першого**: спершу
розкладаємо по категоріях, а вже внутри кожної категорії — за ціною.

Аналогія: сортуємо клас спочатку за паралеллю, потім за прізвищем. Прізвища
впорядковані **всередині** кожного класу, а не по всій школі.

### 3. Створення й видалення (7 хв)

```sql
CREATE DATABASE School97;
DROP DATABASE School97;
DROP DATABASE IF EXISTS School97;   -- не дасть помилки, якщо бази немає
```

```sql
CREATE TABLE School.Students (
    ID INT PRIMARY KEY,
    FirstName NVARCHAR(50),
    LastName NVARCHAR(50),
    PhoneNumber NVARCHAR(50)
);

DROP TABLE IF EXISTS School.Students;
```

⚠⚠ `DROP DATABASE` видаляє **все** без питань і без кошика. Скажи це вголос.
`IF EXISTS` тут не про безпеку — воно лише прибирає помилку «такої бази немає»,
а не захищає від видалення.

### 4. Типи даних (12 хв)

Не давай перелік на 30 позицій — давай **вибір**. Головна таблиця уроку:

| Що зберігаємо | Тип | Чому саме він |
|---|---|---|
| кількість, id, вік | `INT` | цілі числа, 4 байти |
| дуже великі числа | `BIGINT` | коли `INT` мало (понад 2 мільярди) |
| маленькі числа (0–100) | `SMALLINT` | економія пам'яті |
| **гроші, ціни** | `DECIMAL(10,2)` | точність; ⚠ **не `FLOAT`** |
| наукові виміри | `FLOAT` | де точність до останньої цифри не критична |
| текст будь-якої мови | `NVARCHAR(n)` | ⚠ для української **тільки так** |
| текст лише латиницею фіксованої довжини | `CHAR(n)` | коди країн, `UA`, `PL` |
| дата без часу | `DATE` | день народження, дата замовлення |
| дата з часом | `DATETIME2` | момент події |
| так / ні | `BIT` | 0 або 1 |
| унікальний ідентифікатор | `UNIQUEIDENTIFIER` | GUID у розподілених системах |

Три правила вибору, які варто продиктувати:

1. **Найменший тип, у який влізуть усі можливі значення.** Вік — `SMALLINT`,
   не `BIGINT`.
2. **Гроші ніколи не `FLOAT`.** `FLOAT` зберігає приблизно, і на тисячі
   операцій копійки розходяться. Для грошей `DECIMAL`.
3. **Дату не тримають текстом.** Інакше не відсортуєш і не відніміш одну дату
   від іншої.

> Питання класу: **чому номер телефона зберігають як текст, а не як число?**
> Бо в ньому бувають `+`, дужки й пробіли, а провідний нуль число не збереже.
> І бо з номером телефона не роблять арифметики. Гарне питання на розуміння:
> тип вибирають не за виглядом даних, а за тим, **що з ними робитимуть**.

Специфічні типи SQL Server згадай одним рядком, не більше: `XML`,
`GEOGRAPHY` (широта й довгота), `HIERARCHYID` (дерева), `ROWVERSION`.

### 5. NULL (7 хв — головна ідея)

**`NULL` — це не нуль, не порожній рядок і не пробіл.** Це позначка «значення
невідоме».

Три різні речі в стовпці «вага товару»:

| Значення | Що означає |
|---|---|
| `0` | важить нуль — тобто ми виміряли |
| `''` | порожній текст (для числа не буває) |
| `NULL` | **ми не знаємо, скільки він важить** |

Перевірка тільки через `IS`:

```sql
SELECT * FROM SalesLT.Product WHERE Weight IS NULL;      -- вага НЕ вказана
SELECT * FROM SalesLT.Product WHERE Weight IS NOT NULL;  -- вага вказана
```

⚠⚠ `WHERE Weight = NULL` **не працює й не видає помилки** — просто повертає
нуль рядків. Причина: порівняння з невідомим дає не «так» і не «ні», а
«невідомо», а `WHERE` пропускає лише «так».

🖥 Покажи на проекторі три запити поспіль:

```sql
SELECT COUNT(*) FROM SalesLT.Product;                    -- усі
SELECT COUNT(*) FROM SalesLT.Product WHERE Weight IS NULL;
SELECT COUNT(*) FROM SalesLT.Product WHERE Weight = NULL;   -- 0
```

Третій рядок — і є та тиха помилка, яку клас мусить побачити своїми очима.

Зв'яжи з днем 7: **саме через це на минулому уроці не зійшлись числа в кроці з
`NOT IN`** — рядки з `NULL` у колонці `Color` не потрапили ні в `IN`, ні в
`NOT IN`. Якщо хтось на дні 7 це помітив, зараз він отримує відповідь.

`NOT NULL` при створенні таблиці означає «це поле обов'язкове»:

```sql
CREATE TABLE School.Students (
    ID INT PRIMARY KEY,
    LastName NVARCHAR(50) NOT NULL,   -- прізвище обов'язкове
    Email NVARCHAR(100) NULL          -- пошту можна не вказувати
);
```

## ⚠ Що піде не так

| Симптом | Причина | Що робити |
|---|---|---|
| `WHERE ... = NULL` дає 0 рядків без помилки | порівняння з `NULL` | `IS NULL` |
| Замість українських літер знаки питання | `VARCHAR` замість `NVARCHAR`, або забуто `N'…'` | `NVARCHAR` + `N'Іваненко'` |
| `ORDER BY` за двома стовпцями «не працює» | другий діє лише в межах однакових значень першого | розділ 2, аналогія з класами |
| Ціна після обчислень «поїхала» на копійки | `FLOAT` для грошей | `DECIMAL(10,2)` |
| `Cannot drop database because it is currently in use` | база вибрана в редакторі | перемкнутись на `master`: `USE master;` |
| Обчислений стовпець без імені | немає `AS` | додати псевдонім |

## Урок 2 — практика: відповіді й критерії

Учнівський файл: `day-08-practice.md`. Файл здачі — `day08.sql`.

### Відповіді

**Крок 1. Псевдоніми**

```sql
SELECT FirstName + ' ' + LastName AS FullName FROM SalesLT.Customer;

SELECT Name, ListPrice, ListPrice * 0.8 AS PriceWithDiscount
FROM SalesLT.Product;
```

⚠ Якщо в когось у `FullName` вийшов `NULL` — це не помилка, а найкращий
можливий момент: **текст + `NULL` дає `NULL`**. Один невідомий доданок робить
невідомим усе. Такий учень уже готовий до дня 15 (`ISNULL`).

**Крок 2. Сортування**

```sql
SELECT Name, ListPrice FROM SalesLT.Product ORDER BY ListPrice DESC;
SELECT Name, ProductCategoryID, ListPrice FROM SalesLT.Product
ORDER BY ProductCategoryID ASC, ListPrice DESC;
```

Питання про різницю з `ORDER BY ListPrice DESC, ProductCategoryID ASC` —
перевірка розуміння. Відповідь: у другому випадку категорії розсипані, бо
головним стало сортування за ціною.

**Крок 3. Своя база**

```sql
CREATE DATABASE School97;
GO
USE School97;
GO
CREATE SCHEMA Club;
GO
```

⚠ `GO` між командами обов'язкове: `CREATE SCHEMA` мусить бути першою
командою в пакеті. Це найчастіша технічна перепона кроку — попередь заздалегідь
або дай натрапити й підказати.

**Крок 4. Таблиці з правильними типами**

Очікуваний результат (варіанти можливі):

```sql
CREATE TABLE Club.Members (
    ID INT PRIMARY KEY,
    LastName NVARCHAR(50) NOT NULL,
    FirstName NVARCHAR(50) NOT NULL,
    BirthDate DATE NULL,
    Phone NVARCHAR(20) NULL,
    IsActive BIT NOT NULL
);

CREATE TABLE Club.Payments (
    ID INT PRIMARY KEY,
    MemberID INT NOT NULL,
    Amount DECIMAL(10,2) NOT NULL,
    PaidAt DATETIME2 NOT NULL
);
```

Що перевіряти в типах:

| Стовпець | Правильно | Типова помилка |
|---|---|---|
| прізвище | `NVARCHAR` | `VARCHAR` — українська зламається |
| сума | `DECIMAL(10,2)` | `FLOAT` або `INT` |
| телефон | `NVARCHAR` | `INT` — загубить `+` і провідний нуль |
| дата народження | `DATE` | `NVARCHAR` — не відсортуєш |
| активний | `BIT` | `NVARCHAR('так')` |

**Крок 5. Експерименти з NULL**

Послідовність в учнівському файлі. Очікувані спостереження:

1. Рядок із `NULL` у `Phone` вставляється — бо стовпець дозволяє `NULL`.
2. Рядок без прізвища **не** вставляється: `Cannot insert the value NULL into
   column 'LastName'`.
3. `WHERE Phone = NULL` → 0 рядків, без помилки.
4. `WHERE Phone IS NULL` → знайшов.
5. `1 + NULL` → `NULL`.
6. `COUNT(*)` і `COUNT(Phone)` дають **різні** числа: `COUNT(стовпець)` не
   рахує `NULL`.

⚠ Пункт 6 — найцінніший, він знадобиться на дні 12 (агрегатні функції). Хай
учень запише спостереження словами.
