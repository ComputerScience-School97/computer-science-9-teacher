## Виклад

### 1. Від SQL до Python (6 хв)

Це не просто «нова тема» — це зміна способу мислення, і варто назвати її прямо.

| | SQL | Python |
|---|---|---|
| Стиль | **декларативний**: кажеш, що хочеш | **імперативний**: кажеш, як це зробити |
| Хто вирішує порядок дій | база | ти |
| Типи | задаються при створенні таблиці, змінити важко | визначаються самі, змінюються на льоту |

Приклад на дошці — одна й та сама задача «товари дорожчі за 100»:

```sql
SELECT Name FROM Product WHERE ListPrice > 100;
```

```python
for product in products:
    if product["price"] > 100:
        print(product["name"])
```

У SQL немає слів «для кожного» й «якщо» — база сама вирішує, як перебирати. У
Python ти пишеш перебір власноруч.

> Питання класу: **який спосіб кращий?** Ні той ні той. SQL сильний там, де
> треба дістати дані з мільйонів рядків. Python сильний там, де з даними треба
> **щось зробити**: порахувати, намалювати графік, надіслати листа. Тому їх і
> використовують разом — про це буде день 29.

### 2. Змінні (8 хв)

**Змінна** — іменована ділянка пам'яті, у якій лежить значення.

```python
name = "Аліса"
age = 15
height = 1.62
is_student = True
```

**Динамічна типізація** — тип не оголошують, Python визначає його сам за
значенням.

```python
x = 10        # тепер це int
x = "текст"   # а тепер str, і це не помилка
```

⚠ Порівняй із SQL: там стовпець `INT` не стане текстовим ніколи. Тут — стане.
Це зручно й одночасно є джерелом помилок, які видно лише при запуску.

**Правила імен:**

- починається з літери або `_`, далі літери, цифри, `_`
- **регістр важливий**: `age` і `Age` — різні змінні
- не можна вживати службові слова (`if`, `for`, `class`, `print` краще теж не
  займати)

Про стиль скажи одразу, бо потім переучувати важко: у Python імена змінних
пишуть **малими літерами з підкресленнями** — `student_name`, не
`StudentName`. Це не примха, це загальна домовленість `snake_case`.

### 3. Типи даних (16 хв, головна частина)

**Числові:**

```python
num1 = 10           # int — цілі, будь-якого розміру
num2 = -25
num3 = 3.14         # float — з дробовою частиною
num4 = -0.001
complex_num = 2 + 3j   # complex — комплексні, у наукових обчисленнях
```

⚠ Одна деталь, яку варто показати одразу, бо вона здивує:

```python
print(0.1 + 0.2)      # 0.30000000000000004
```

Це не помилка Python — так працюють числа з плаваючою комою в **будь-якій** мові.
Зв'яжи з днем 8: саме тому гроші в базі зберігають у `DECIMAL`, а не `FLOAT`.
Тут та сама причина.

**Текст:**

```python
greeting = "Привіт, світ!"
character = 'A'
long_text = """Багаторядковий
текст у трьох лапках"""
```

Одинарні й подвійні лапки рівноправні. Три лапки — для багаторядкового тексту.

Операції, які варто показати:

```python
print("Привіт" + ", " + "світ")   # склеювання
print("ха" * 3)                    # хахаха
print(greeting[0])                 # П — перший символ
print(len(greeting))               # довжина
```

⚠ Індексація **з нуля**. `greeting[0]` — перший символ. Це джерело помилок на
весь блок, скажи двічі.

**Логічний:**

```python
is_active = True
is_deleted = False
```

⚠ З великої літери: `True`, не `true`. Учні, які писали SQL або дивились
JavaScript, помиляються тут регулярно.

**`None`** — «немає значення»:

```python
result = None
```

Зв'яжи з `NULL` із дня 8: це та сама ідея. І та сама пастка — перевіряти треба
`if result is None`, а не `== None` (працює, але так не пишуть).

### 4. Колекції — оглядово (8 хв)

Тільки назвати й показати вигляд. Детально: списки — день 21, решта — день 22.

```python
fruits = ["яблуко", "банан", "черешня"]   # list — змінюваний, за порядком
dimensions = (1920, 1080)                  # tuple — НЕзмінюваний
student = {"name": "Аліса", "age": 15}     # dict — ключ → значення
unique = {1, 2, 3, 4, 4, 5}                # set — унікальні, без порядку
```

```python
print(fruits[0])         # яблуко
print(student["name"])   # Аліса
print(unique)            # {1, 2, 3, 4, 5} — четвірка одна
```

⚠ Зверни увагу класу на `set`: дублікат зник сам. Питання: **де ми таке вже
бачили?** `SELECT DISTINCT` з дня 7. Такі зшивки з SQL-блоком варто робити щоразу,
коли трапляється нагода — вони помітно допомагають.

### 5. Перетворення типів (5 хв)

```python
num = "123"
num_int = int(num)        # 123
num_float = float(num)    # 123.0
text = str(456)           # "456"
items = list("abc")       # ['a', 'b', 'c']
```

Практичний контекст, який робить це не абстракцією:

```python
age = input("Скільки тобі років? ")   # input завжди дає РЯДОК
print(age + 1)                         # ⚠ TypeError!
print(int(age) + 1)                    # так правильно
```

🖥 Покажи саму помилку на проекторі:
`TypeError: can only concatenate str (not "int") to str`. Її отримає весь клас,
і краще, щоб вони її вже бачили.

⚠ `int("привіт")` дасть `ValueError`. Отже перетворення може впасти — і це
причина, чому на дні 26 буде тема обробки винятків.

## ⚠ Що піде не так

| Симптом | Причина | Що робити |
|---|---|---|
| `python: command not found` | Python не в `PATH` | перевстановити з галочкою `Add Python to PATH`, або запускати кнопкою ▷ у VS Code |
| `TypeError: can only concatenate str…` | склеюють текст із числом | `int()` або `str()` |
| `NameError: name 'age' is not defined` | описка або інший регістр | `age` ≠ `Age` |
| `SyntaxError` через `true` | у Python `True` | з великої літери |
| `0.1 + 0.2` не дає `0.3` | так працює `float` | розділ 3; зв'язати з `DECIMAL` із дня 8 |
| Файл запускається не той | у VS Code відкрито кілька файлів | дивитись, який файл активний |

### Крок 4. Числа

Очікуване спостереження: `0.1 + 0.2` не дає рівно `0.3`. Обов'язковий висновок,
який зшиває з SQL-блоком: **для грошей `float` не годиться, як і в базі даних**.

Ділення:

```python
print(7 / 2)    # 3.5   — завжди float
print(7 // 2)   # 3     — ціла частина
print(7 % 2)    # 1     — остача
print(2 ** 10)  # 1024  — степінь
```

⚠ `%` (остача) знадобиться на дні 20 для перевірки на парність — назви це
заздалегідь.

### Крок 5. Текст

```python
text = "Програмування"
print(len(text))       # 13
print(text[0])         # П
print(text[-1])        # я — останній символ
print(text.upper())
print(text[0:5])       # Програ
```

⚠ `text[-1]` — приємна знахідка, учні її запам'ятають. А `text[13]` дасть
`IndexError: string index out of range`, і це варто дати натрапити самому:
довжина 13, а індекси від 0 до 12.

### Крок 6. input і перетворення

Головний крок практики. Послідовність обов'язкова: спершу помилка, потім

Далі — `int("привіт")` і `ValueError`. Питання: **що зробити, щоб програма не
